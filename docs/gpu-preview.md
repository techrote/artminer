# AM-004 D3D11 interactive preview

The interactive ArtMiner window uses a native Win32/D3D11/DXGI presentation path. This path is deliberately separate from the **canonical CPU/reference evaluator** introduced in AM-003.

## Canonical versus preview semantics

The CPU `render_reference()` path remains the normative evaluator for golden tests, archival rendering, and the existing headless `ArtMiner render` command. AM-004 does not change its recipe, raster, seed, colour, or RGBA8 semantics.

The D3D11 preview is an acceleration/display path. Floating-point shader results are not claimed to be bit-identical across all GPU/driver combinations. The UI therefore states which path produced the current preview:

- **GPU preview** — generated by the AM-004 HLSL evaluator and shown through D3D11;
- **canonical CPU fallback** — generated by `render_reference()` and uploaded to D3D11 for presentation.

A fallback is semantic preservation, not an alternate interpretation. Unsupported nodes never receive an approximate replacement.

## GPU-supported subset

AM-004 generates a shader for pointwise graphs composed from the following implemented operations where the GPU expression has a direct correspondence to the canonical evaluator:

- scalar constant/pass and normalized X/Y coordinates;
- radial and angular fields;
- circle and box signed-distance fields;
- scalar minimum/maximum, threshold, and quantisation;
- colour composition and scalar extraction from colour;
- built-in mono/warm/cool palettes and two-colour gradient palettes;
- linear/nearest palette mapping;
- scalar-to-image, colour-to-image, and Bayer 4×4/8×8 ordered dithering.

AM-004 intentionally leaves the following on canonical CPU fallback:

- value, gradient, Worley, and fBm noise;
- domain warp;
- raster repeat and symmetry transforms;
- vector-field paths not consumed by the pointwise image subset;
- stateful/particle/state-boundary nodes.

This is deliberate. Several AM-003 operations materialize intermediate raster fields and then resample them. Replacing those semantics with a superficially similar analytic shader would be faster but would not be an honest CPU/GPU equivalence implementation.

The committed `am003-sdf.amr` example exercises the GPU path. The fBm/warp, Worley, and angular/repeat examples remain fully usable interactively through explicit canonical CPU fallback.

## Shader and runtime dependencies

Shader source is generated deterministically from the validated recipe and compiled with the Windows SDK/system D3D compiler (`D3DCompile`, shader model 5.0). ArtMiner adds no third-party shader compiler, GUI framework, package manager, telemetry component, or network dependency.

The interactive device creation path prefers D3D11 hardware and falls back to the Windows WARP software rasterizer if hardware device creation is unavailable. CI equivalence testing uses WARP explicitly so the tested path does not depend on a hosted runner exposing a physical GPU.

## Equivalence tests and tolerances

The canonical CPU image is always the oracle. `ArtMinerGpuTests` compares a representative GPU-supported recipe against D3D11 WARP output and also verifies that an unsupported graph returns the canonical image byte-for-byte through fallback.

The AM-004 WARP comparison records maximum channel error, mean absolute channel error, and differing-channel count. Smooth pointwise operations are expected to differ only by normal CPU-double versus shader-float rounding. Discontinuous threshold/SDF boundaries are assessed primarily by aggregate error because a sub-pixel floating-point sign difference can legitimately select opposite sides of a hard boundary at a small number of pixels. Tolerances belong to the test fixture and must not be widened merely to obtain green CI; any widening requires a documented semantic reason.

Node-level AM-003 CPU goldens remain unchanged and authoritative.

## Resize, model ownership, and device loss

Window resizing changes only the swap-chain/back-buffer dimensions and the display scaling of the already evaluated recipe image. It does **not** rewrite `Recipe::render`, graph parameters, seed, or semantic fingerprint.

The D3D11 presenter owns its COM resources explicitly. `ResizeBuffers` releases/recreates back-buffer views. `DXGI_ERROR_DEVICE_REMOVED` and `DXGI_ERROR_DEVICE_RESET` trigger device/swap-chain reconstruction and rebuild the preview from the stored validated recipe. The recipe is authoritative; GPU resources are disposable.

The GUI checks the recipe semantic fingerprint across preview loading. UI layout, menu actions, status updates, frame presentation, and resize events are not model edits.

## Interactive controls and diagnostics

Run `ArtMiner.exe` with no headless command to open the native preview. Use **File → Open Recipe…** or **Ctrl+O**, or launch directly with:

```bat
ArtMiner.exe --open examples\am003-sdf.amr
```

The status strip reports the recipe name, recipe raster dimensions, semantic fingerprint, current GPU/fallback path, hardware-versus-WARP device type, presented frame count, and last presentation duration. These diagnostics are local process state only; ArtMiner sends no telemetry.
